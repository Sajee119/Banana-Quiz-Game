What you must demonstrate

Your video must relate event-driven programming to your own code. At minimum you need to mention events and relate them to specific handlers. To score higher, you must identify the different event types in your application, explain the mechanism that dispatches and handles them, and ultimately justify your event-handling design (for 70%+).

Threshold expectation: explain the key concept of events based on the code you have developed. Simply saying "I used addEventListener" without connecting it to the event types and handlers in your project keeps you in the 40–49% band.

Evidence from your code

Show a real handler from your Banana API game and explain each part:

game.js · event handler 
// Event: user submits a guess
const guessForm = document.querySelector('#guess-form');

guessForm.addEventListener('submit', async (event) => {
  event.preventDefault();                 // stop page reload
  const guess = event.target.guess.value;

  try {
    const result = await BananaClient.checkGuess(guess);
    GameUI.updateFeedback(result);   // event → state → UI
  } catch (err) {
    GameUI.showError(err.message);
  }
});

// Custom event: emitted when a round ends
document.addEventListener('round:complete', (e) => {
  ScoreBoard.render(e.detail.score);
});

What to say in your video

Event types

List the events in your app (submit, click, custom round:complete) and say where each originates — user, API response, or timer.

Handler mechanism

Explain how the browser/runtime dispatches events, how your listeners are registered, and how preventDefault / propagation affect behaviour.

Separation of concerns

Show how handlers stay thin — they delegate to BananaClient and GameUI — keeping event logic decoupled from business logic.

Justification (70%+)

Justify your approach vs alternatives: callbacks vs promises vs async/await, or global vs delegated listeners. Explain why your choice suits this game.

Pre-submission checklist

  • At least two real event types from your code are shown and named.
  • The dispatch-to-handler mechanism is explained, not just listed.
  • Custom events (if used) are highlighted and explained.
  • Handlers shown to be thin and delegated to services/UI modules.
  • For 70%+: a justification of your event approach vs at least one alternative.
  • All external code (GitHub, LLMs, forums) referenced in code comments.
