Interoperability

Theme 3 of 4 · CIS046-3 Software For Enterprise · Assignment 1 (60%)

What you must demonstrate

Your video must relate interoperability to your own code. At minimum you must mention it and connect it to your project. Higher bands require you to identify where your code interoperates with someone else's code and what protocol is used (50–59%), reflect on how your code works with a different architecture or remote system (60–69%), and critically justify your approach to including third-party software such as the Banana API (70%+).

Threshold expectation: explain the key concept of interoperability based on the code you have developed. The Banana API is the obvious candidate — but you can also discuss how your chosen language interoperates with the browser, a database, or another service.

Evidence from your code

Show the integration layer as a separate module, so you can talk about encapsulation:

banana-client.js · integration layer 
// Third-party integration: Banana API
// Docs: https://marcconrad.com/uob/banana/doc.php
// Protocol: HTTPS (REST) · Data format: JSON

export class BananaClient {
  static async checkGuess(guess) {
    const url = `https://marcconrad.com/uob/banana/api.php?question=${encodeURIComponent(guess)}`;

    const response = await fetch(url, {
      method: 'GET',
      headers: { 'Accept': 'application/json' },
    });

    if (!response.ok) {
      throw new Error(`Banana API error: ${response.status}`);
    }

    // Contract check: validate shape before trusting it
    const data = await response.json();
    if (typeof data.correct !== 'boolean') {
      throw new Error('Unexpected API response shape');
    }
    return data;
  }
}

Tip: mention error handling, timeouts, and contract validation — these show you understand the risks of depending on someone else's code.

What to say in your video

Where the boundary sits

Name the exact module (BananaClient) that talks to the external service, and show that the rest of your code never calls the API directly.

Protocols used

Say "HTTPS GET request returning JSON over REST" and explain why these choices interoperate cleanly with a JavaScript/Java client.

Different architecture

Discuss how your client runs on a different system (browser / JVM) from the server-side API, and how the HTTP contract bridges them.

Justification (70%+)

Justify why you chose the Banana API, why you wrapped it in its own class, and how you handle failure (timeouts, malformed JSON, rate limits) vs alternatives.

Pre-submission checklist

  • The external service (e.g. Banana API) is named and its docs are referenced in code comments.
  • The integration layer is isolated in its own module/class.
  • Protocols named explicitly: HTTPS, REST, JSON.
  • Error handling and response validation are shown and explained.
  • For 70%+: a critical justification of the third-party choice and integration approach.
  • All third-party code (GitHub, LLMs, forums) referenced in code comments.
