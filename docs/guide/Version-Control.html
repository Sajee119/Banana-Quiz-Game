Landing Version Control

Version Control

Theme 1 of 4 · CIS046-3 Software For Enterprise · Assignment 1 (60%)

What you must demonstrate

Your video must relate version control directly to your own code. At minimum you need to show how Git (or an equivalent) tracks your changes and how your codebase is split into components. To reach the higher bands, you must reflect critically on your branching strategy, commit granularity, code reviews, and how version control supports modularity, maintainability and collaboration.

Threshold expectation: explain the key concept of version control based on the code you have developed. If you only "mention" Git without linking it to specific files, components and decisions in your project, you sit in the 40–49% band.

Evidence from your code

Include a short Git history extract and a component map in your video/slides. Example:

Git log 
$ git log --oneline --graph --all
*   a1b2c3d (HEAD -> feature/auth) Merge pull request #4 from auth-refactor
|\
| * 9f8e7d6 Add cookie-based session + bcrypt hashing
| * 4c3b2a1 Create AuthService component (unit tested)
|/
* 7d6c5b4 Refactor BananaAPI client into isolated module
* 3a2b1c0 Initial commit: project scaffold + README

Tip: also show a folder tree (e.g. /src/components, /src/services, /tests) so the marker can see the modular organisation that your commits map onto.

Marking rubric for this theme

Band What the marker looks for
40–49% Mention the basic use of version control tools, such as Git, for tracking changes. Identify that code is organised into various components.
50–59% Clearly identify how version control supports the responsibilities of software components. Reflect on how organised code aids collaboration and efficient management within a version-controlled environment.
60–69% Confidently reflect on how code organisation and version control address modularity, maintainability and collaboration. Discuss specific practices: branch management, commit granularity, and using version control to manage dependencies between components.
70%+ Critically evaluate the structure of your code and its organisation into components, considering alternative approaches. Reflect on how version control strategies (branching, tagging, code reviews) enhance quality, scalability and maintainability.

What to say in your video

Branching strategy

Describe your branching model (e.g. feature branches merged via PR). Explain why you chose it and how it isolated work on your Banana API client from your auth logic.

Commit granularity

Show 2–3 commits and justify why each was a single logical change. Relate this to testability and to reviewing your own code before submission.

Modularity

Map components (e.g. AuthService, BananaClient, GameUI) to folders and to commits. Explain how this makes the codebase maintainable.

Alternatives (70%+)

Critically compare your approach to alternatives: trunk-based vs GitFlow, monorepo vs multi-repo, squash-merging vs merge commits. Say what you would change and why.

Pre-submission checklist

  • Git history visible and referenced in the video (log, branches, merge commits).
  • Folder/component structure shown and linked to commits.
  • Branching strategy explained, not just listed.
  • Commit granularity justified in terms of reviews and maintainability.
  • For 70%+: a critical comparison with an alternative VCS workflow.
  • All external code (GitHub, LLMs, forums) referenced in code comments.
