Evidence from your code

Show the authentication layer as a separate module, so you can talk about separation of concerns:

auth-service.js · identity layer 
// Virtual identity: register + login with hashed passwords
// Uses bcrypt for hashing (external library — referenced below)
// bcrypt: https://www.npmjs.com/package/bcrypt

import bcrypt from 'bcrypt';
import { SessionStore } from './session-store.js';

export class AuthService {
  static async register(username, password) {
    // Never store plaintext passwords
    const hash = await bcrypt.hash(password, 12);
    return UserStore.create({ username, passwordHash: hash });
  }

  static async login(username, password) {
    const user = await UserStore.findByUsername(username);
    if (!user) throw new Error('Invalid credentials');

    const ok = await bcrypt.compare(password, user.passwordHash);
    if (!ok) throw new Error('Invalid credentials');

    return SessionStore.create(user.id); // sets HttpOnly cookie
  }

  static getIdentity(req) {
    return SessionStore.verify(req.cookies.sessionId);
  }
}

Tip: mention why you hash (irreversibility), why the cookie is HttpOnly (blocks XSS theft), and why you return the same error for unknown user and wrong password (prevents user enumeration).

What to say in your video

Password handling

Show where the password is hashed (bcrypt.hash) and verified (bcrypt.compare). Explain why plaintext storage is unacceptable.

Cookies & sessions

Point to the session cookie and explain the flags: HttpOnly, Secure, SameSite. Say what each flag defends against.

Establishing identity

Walk through the flow: login → session token → protected route → getIdentity() returns the user. This is the virtual identity.

Alternatives (70%+)

Critically compare password + bcrypt + cookie sessions against JWT, OAuth/OpenID Connect, passkeys/WebAuthn, or MFA. Discuss trade-offs.

Pre-submission checklist

  • A real login/identity mechanism exists in the code and is shown in the video.
  • Password hashing (or equivalent) is shown, not plaintext comparison.
  • Cookie/session flags are named and their purpose explained.
  • The full flow (login → token → protected route) is explained.
  • For 70%+: at least two alternative approaches are critically compared.
  • All external code/libraries (e.g. bcrypt) referenced in code comments.
